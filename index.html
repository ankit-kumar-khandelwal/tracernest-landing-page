Enterprise Architecture Built Into a Single Package

Every feature in TracerNest was engineered from the ground up to solve the real flaws of existing Node.js & Laravel logging tools.

Zero Extra Ports

Traditional tools force you to open separate ingress ports, exposing new attack surfaces and complicating Kubernetes deployments. TracerNest mounts directly onto your host router.

  • No firewall modifications required
  • Works behind existing SSL & domain reverse proxies
  • Mounts on Express, Koa, Fastify & Laravel 13

Zero Runtime Dependencies

Supply chain attacks via transitive dependencies are the #1 vulnerability vector in modern npm packages. TracerNest has exactly dependencies: {}.

  • 100% native Node.js standard library
  • No Dependabot or CVE audit alerts
  • Lightweight ~15MB footprint vs ~60MB+ bloat

AES-256-GCM Payload Encryption

Never store user passwords, authorization tokens, or sensitive medical/financial data in plaintext logs. Every payload is encrypted at rest using hardware-accelerated AES-256-GCM.

  • Master key never hardcoded in repository
  • Tamper-proof 128-bit authentication tag verification
  • HIPAA & GDPR compliance ready

SQLite to MySQL Auto-Migration

Start instantly in local development with embedded SQLite. When scaling to production, simply pass your MySQL connection string — TracerNest automatically migrates your schema and data.

  • Zero-downtime automated column schema drift DDL
  • Automatic safe cleanup of SQLite files
  • Strict preservation of your .master.key

Persistent Logs Until TTL Completion

Most embedded loggers lose in-memory logs whenever your server restarts or Docker spins up a fresh container. TracerNest writes directly to disk/DB with configurable TTL cleanup.

  • Logs survive unexpected container crashes
  • Configurable TTL (7, 14, 30, 90 days)
  • Zero memory leaks under high-throughput spikes

Laravel 13 PHP Bridge

TracerNest isn't restricted to Node.js. It features a native Laravel 13 PHP middleware and controller bridge, enabling unified telemetry across your entire polyglot backend stack.

  • Zero-port Laravel route integration
  • Captures PHP exceptions, request headers & DB queries
  • Unified single-pane-of-glass dashboard

Why Zero Extra Ports Matter

When running in Kubernetes, Docker Swarm, or AWS ECS, every exposed port requires another target group, security group ingress rule, ALB path routing rule, and firewall punch. TracerNest eliminates this complexity completely by attaching to your existing HTTP server handler.

True Zero-Dependency Security

Every additional npm dependency introduces attack vectors like malicious sub-dependency takeovers or silent CVEs. TracerNest's HTTP router, crypto suite, template engine, and storage adapters are written purely using Node.js built-ins, keeping your audit clean.

Zero Egress Cloud Data Privacy

Datadog and Sentry require streaming sensitive user data to external third-party cloud servers, posing significant compliance hurdles under GDPR, HIPAA, and SOC2. With TracerNest, your telemetry data never leaves your infrastructure.

Got Questions?

Frequently Asked Questions

What is the best Errsole alternative for Node.js?

TracerNest is widely recognized as the premier self-hosted alternative to Errsole for Node.js, Express, Koa, and Fastify. Unlike Errsole, TracerNest has strictly zero runtime dependencies (dependencies: {} in package.json), embeds directly into your existing HTTP port without opening additional TCP ports, secures all logs with hardware-accelerated AES-256-GCM encryption, and supports seamless auto-migration from SQLite to MySQL without vendor lock-in.

How to persist Express logs after server restart?

TracerNest persists Express application logs by streaming records directly to local SQLite files or a remote MySQL database using synchronous Write-Ahead Logging (WAL). Unlike memory-only loggers that lose state during process crashes, Docker container restarts, or Kubernetes pod rescheduling, TracerNest logs remain persistent on disk until your configured TTL retention cycle gracefully archives them.

How to view Node.js logs in a browser without opening extra ports?

TracerNest attaches directly as standard middleware on your existing Node.js HTTP router (e.g. app.use(tracerNest({ path: '/tracernest' }))). When you navigate to your designated path in your web browser, TracerNest intercepts the request internally and serves the responsive real-time web dashboard directly over your primary application port—completely eliminating firewall changes, ingress updates, or separate open ports.

How to encrypt application logs in Node.js?

With TracerNest, log encryption is automatic and zero-configuration. TracerNest uses Node.js's native node:crypto engine to encrypt every recorded log message, request header, and stack trace using hardware-accelerated AES-256-GCM with authenticated 128-bit integrity tags. The high-entropy 256-bit encryption key is stored securely in your project's local .master.key (file mode 0600) and never transmitted to external clouds or third-party servers.

How to monitor Express API requests locally?

Simply register TracerNest as your first middleware in Express: app.use(tracerNest()). It automatically intercepts all incoming HTTP requests, recording the HTTP method, endpoint route, response status code (200, 404, 500), execution duration in milliseconds, memory footprint, and correlated request IDs. You can inspect live API requests with real-time level filtering (ERROR, WARN, INFO, HTTP) in the embedded dashboard.

How to build a self-hosted logging dashboard in Node.js?

Instead of building a custom telemetry dashboard from scratch with WebSockets and frontend frameworks, or deploying heavy ELK (Elasticsearch/Logstash/Kibana) stacks, install tracernest-logger. With a single npm command, you get an enterprise-grade self-hosted logging dashboard complete with search, tag filtering, AES-256-GCM encryption, SQLite/MySQL persistence, and HTTP Basic Auth security.

Why choose TracerNest as a self-hosted alternative to Datadog?

Commercial APM platforms like Datadog, New Relic, and Dynatrace charge aggressive per-host and per-gigabyte ingestion fees that quickly reach $250 to $2,500+ every month. TracerNest provides a 100% free, open-source, self-hosted alternative that runs entirely within your existing infrastructure, eliminating cloud SaaS egress fees while ensuring absolute compliance with strict data sovereignty mandates (GDPR, HIPAA, SOC2).

How does TracerNest compare as a Winston and Pino alternative?

Traditional loggers like Winston and Pino are stdout/stderr stream formatters—they do not provide a built-in web dashboard, at-rest payload encryption, or automatic database migration. TracerNest acts as a complete telemetry flight recorder: it captures logs with zero runtime dependencies (unlike Winston's 12+ packages), encrypts payloads at rest with AES-256-GCM, and serves an interactive web dashboard on your application port.

Is there a Node.js logger with zero dependencies?

Yes, TracerNest (tracernest-logger) is engineered with strictly zero third-party runtime dependencies. The dependencies object in package.json is completely empty ({}). All telemetry collection, cryptographic hashing, AES-256-GCM encryption, SQLite persistence, and web dashboard rendering rely exclusively on built-in Node.js standard libraries (node:crypto, node:http, node:fs, node:sqlite), completely eliminating node_modules bloat and supply-chain vulnerabilities.

How do I add an encrypted log viewer to a Laravel application?

TracerNest provides native support for Laravel 13 through its lightweight PHP bridge. Simply bind the TracerNest Monolog driver in your config/logging.php and route middleware in bootstrap/app.php. For detailed setup guides, controller timing examples, and microservices correlation, visit our dedicated Laravel Logging Dashboard page →

How do I migrate logs from SQLite to MySQL without downtime?

TracerNest performs automated zero-downtime database migration. When you change your initialization configuration from local SQLite to MySQL, TracerNest automatically inspects the MySQL schema, executes non-destructive DDL (ALTER TABLE ... ADD COLUMN ...) for missing tables and columns, migrates all historical SQLite records into MySQL, and safely cleans up old SQLite files while keeping your .master.key intact.

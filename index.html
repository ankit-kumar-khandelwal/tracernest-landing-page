Enterprise Architecture Built Into a Single Package

Every feature in TracerNest was engineered from the ground up to solve the real flaws of existing Node.js & Laravel logging tools.

Zero Extra Ports

Traditional tools force you to open separate ingress ports, exposing new attack surfaces and complicating Kubernetes deployments. TracerNest mounts directly onto your host router.

  • No firewall modifications required
  • Works behind existing SSL & domain reverse proxies
  • Mounts on Express, Koa, Fastify & Laravel 13

Zero Runtime Dependencies

Supply chain attacks via transitive dependencies are the #1 vulnerability vector in modern npm packages. TracerNest has exactly dependencies: {}.

  • 100% native Node.js standard library
  • No Dependabot or CVE audit alerts
  • Lightweight ~15MB footprint vs ~60MB+ bloat

AES-256-GCM Payload Encryption

Never store user passwords, authorization tokens, or sensitive medical/financial data in plaintext logs. Every payload is encrypted at rest using hardware-accelerated AES-256-GCM.

  • Master key never hardcoded in repository
  • Tamper-proof 128-bit authentication tag verification
  • Hardware-Accelerated AES-256-GCM Encryption

SQLite to MySQL Auto-Migration

Start instantly in local development with embedded SQLite. When scaling to production, simply pass your MySQL connection string — TracerNest automatically migrates your schema and data.

  • Zero-downtime automated column schema drift DDL
  • Automatic safe cleanup of SQLite files
  • Strict preservation of your .master.key

Persistent Logs Until TTL Completion

Most embedded loggers lose in-memory logs whenever your server restarts or Docker spins up a fresh container. TracerNest writes directly to disk/DB with configurable TTL cleanup.

  • Logs survive unexpected container crashes
  • Configurable TTL (7, 14, 30, 90 days)
  • Zero memory leaks under high-throughput spikes

Laravel 13 PHP Bridge

TracerNest isn't restricted to Node.js. It features a native Laravel 13 PHP middleware and controller bridge, enabling unified telemetry across your entire polyglot backend stack.

  • Zero-port Laravel route integration
  • Captures PHP exceptions, request headers & DB queries
  • Unified single-pane-of-glass dashboard

Why Zero Extra Ports Matter

When running in Kubernetes, Docker Swarm, or AWS ECS, every exposed port requires another target group, security group ingress rule, ALB path routing rule, and firewall punch. TracerNest eliminates this complexity completely by attaching to your existing HTTP server handler.

True Zero-Dependency Security

Every additional npm dependency introduces attack vectors like malicious sub-dependency takeovers or silent CVEs. TracerNest's HTTP router, crypto suite, template engine, and storage adapters are written purely using Node.js built-ins, keeping your audit clean.

Zero Egress Cloud Data Privacy

Datadog and Sentry require streaming sensitive user data to external third-party cloud servers, exposing internal payloads to potential third-party security vulnerabilities. With TracerNest, your telemetry data never leaves your infrastructure.

Got Questions?

Frequently Asked Questions

What is the best Errsole alternative for Node.js?

TracerNest is an open-source, self-hosted alternative for Node.js developers looking for an integrated logging dashboard and encrypted log storage. It attaches directly to your existing HTTP server pipeline with zero external dependencies.

Read the Errsole alternative technical architecture guide →

How to persist Express logs after server restart?

TracerNest writes log records directly to persistent storage—either local SQLite files using synchronous Write-Ahead Logging (WAL) or a centralized MySQL database—rather than volatile process memory. Logs survive unhandled exceptions, Docker container restarts, and Kubernetes pod rescheduling until your configured TTL expires.

Read the log persistence & distributed tracing architecture guide →

How to view Node.js logs in a browser without opening extra ports?

TracerNest mounts as standard middleware into your application's existing HTTP pipeline (Express, Koa, or Fastify). When you navigate to your configured dashboard path (such as /tracernest), TracerNest handles the request internally and serves the web dashboard over your primary application port without requiring firewall changes or reverse proxy reconfiguration.

Read the Express log viewer setup tutorial →

How to encrypt application logs in Node.js?

TracerNest uses Node.js standard node:crypto to encrypt log records at rest using hardware-accelerated AES-256-GCM. Each record receives a unique 96-bit initialization vector and a 128-bit authentication tag, derived from a locally managed 256-bit key in .master.key (file mode 0600) without third-party dependencies.

Read the AES-256-GCM log encryption guide →

How to monitor Express API requests locally?

Register TracerNest middleware at the top of your Express app (app.use(tracerNest())). It automatically records incoming HTTP methods, route paths, status codes, execution duration in milliseconds, memory consumption, and correlation IDs. You can inspect requests in real time with level filtering in the embedded viewer.

Read the Express telemetry & route profiling guide →

How to build a self-hosted logging dashboard in Node.js?

Rather than building custom WebSocket viewers or maintaining an ELK stack, installing tracernest-logger provides an embedded, self-contained dashboard. It includes level filtering, real-time search, authenticated AES-256-GCM encryption, and SQLite/MySQL storage with zero runtime dependencies.

Read the native Node.js logger architecture deep dive →

Why choose TracerNest as a self-hosted alternative to Datadog?

Commercial APM platforms charge variable per-host and per-gigabyte ingestion fees. TracerNest is a self-hosted alternative that stores logs entirely within your own SQLite or MySQL infrastructure, avoiding external data egress costs while keeping telemetry completely private within your own infrastructure.

Read the global telemetry & self-hosting architecture guide →

How does TracerNest compare as a Winston and Pino alternative?

Winston and Pino are stream emitters that format output for terminals or files without a built-in UI or at-rest encryption. TracerNest combines a logging engine with an embedded web viewer, native AES-256-GCM encryption, and zero runtime dependencies in a single package.

Read the full Winston vs. Pino vs. TracerNest comparison →

Is there a Node.js logger with zero dependencies?

Yes. TracerNest has an empty dependencies: {} object in package.json. All HTTP routing, cryptography, file operations, and SQLite access rely exclusively on native Node.js standard libraries (node:crypto, node:http, node:fs, node:sqlite). This reduces exposure to third-party runtime dependency vulnerabilities through its zero-runtime-dependency architecture.

Read the zero-dependency supply chain security guide →

How do I add an encrypted log viewer to a Laravel application?

TracerNest provides native support for Laravel 13 via a custom Monolog driver in config/logging.php and HTTP route middleware in bootstrap/app.php. Telemetry and exception traces stream to the embedded dashboard on your existing web port.

View the dedicated Laravel Logging Dashboard → • Read the Laravel 13 Monolog integration guide →

How do I migrate logs from SQLite to MySQL without downtime?

When switching storage configuration from SQLite to MySQL, TracerNest verifies schema definitions, executes non-destructive DDL (ALTER TABLE ... ADD COLUMN ...) for missing fields, transfers historical records in batches, and cleans up legacy SQLite files while preserving your .master.key.

Read the zero-downtime SQLite to MySQL migration guide →

Quick Start

3-Step Laravel 13 Setup

Get an encrypted dashboard live in your Laravel application in less than 3 minutes.

Step 1: Install the Package

Install the official TracerNest package via Composer and npm:

Terminal
composer require tracernest/laravel
npm install tracernest-logger

Step 2: Add Monolog Channel in config/logging.php

Register the TracerNest custom Monolog driver to automatically capture all framework logs:

PHP (config/logging.php)
'channels' => [
    'stack' => [
        'driver' => 'stack',
        'channels' => ['single', 'tracernest'],
        'ignore_exceptions' => false,
    ],

    'tracernest' => [
        'driver' => 'custom',
        'via' => \TracerNest\Laravel\TracerNestLogger::class,
        'level' => env('LOG_LEVEL', 'debug'),
        'path' => '/tracernest',
        'storage' => env('TRACERNEST_STORAGE', 'sqlite'),
    ],
],

Step 3: Register Middleware in bootstrap/app.php

Attach TracerNest request lifecycle tracking to your global HTTP middleware stack:

PHP (bootstrap/app.php - Laravel 13)
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Middleware;
use TracerNest\Laravel\Http\Middleware\TracerNestTelemetryMiddleware;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware): void {
        $middleware->append(TracerNestTelemetryMiddleware::class);
    })
    ->create();

That's it! Your dashboard is live

Navigate to https://your-domain.test/tracernest to inspect real-time encrypted telemetry, query durations, and exception stack traces.

Got Questions?

Laravel Telemetry & Log Viewer FAQs

How does TracerNest achieve zero extra ports in Laravel 13?

TracerNest registers an internal route handler (/tracernest/{any?}) within Laravel's standard HTTP routing pipeline. When a request matches this route, TracerNest serves the pre-compiled dashboard assets and encrypted API responses directly through your existing web server (Nginx, Apache, or Octane) on ports 80/443 without opening any secondary ports.

Learn more about zero-port HTTP pipeline mounting →

Does TracerNest require background queue workers or Redis?

No. TracerNest is designed for maximum operational simplicity. It utilizes native SQLite with Write-Ahead Logging (WAL) or direct streaming batches to MySQL. It does not require Redis daemons, RabbitMQ queue workers, or external background agents.

Read the SQLite WAL & MySQL architecture guide →

How are logs encrypted at rest in Laravel?

TracerNest utilizes hardware-accelerated AES-256-GCM encryption. Every log payload (headers, exception stack traces, request parameters) is encrypted with a unique 96-bit initialization vector before writing to disk. The 256-bit encryption key is managed securely in .master.key, ensuring plaintext telemetry is never exposed in data backups or server logs.

Read the authenticated AES-256-GCM encryption guide →

How does correlation tracking work between Laravel and Node.js APIs?

When an incoming HTTP request contains an x-request-id or W3C traceparent header, TracerNest captures and propagates that trace ID across both Laravel and Node.js microservices. In the dashboard, you can filter by correlation ID to inspect the full end-to-end journey of a transaction across multiple polyglot services.
